# 标注工具链

用人工标注给自动切分打分。回答的是一句话：**这次改动，到底让片子变好了没有？**

看不到这个数字，改参数就只能靠感觉——而感觉在这个问题上特别不可靠。自动切分的
两类错误方向相反：多切一点，废话少但容易剪掉内容；少切一点，内容保住了但废话留着。
两条路子听起来都合理，不摆到一起量就没法选。

## 为什么必须有人工标注

程序自己的输出不能当答案——拿它的判断去评它自己，永远是满分。要有独立的参照：

1. 从分析结果里**抽一批片段**；
2. **人来听**，逐段判断该留还是该切；
3. 拿这批判断当标准答案，去量程序在**每一次**改动后的表现。

抽出来的片段和标注结果放在各素材自己的目录下，**不进版本管理**——里面是本地媒体
的片段和人工成果。这份 README 和同目录的脚本才是要发布的。

## 两个指标

| 指标 | 定义 | 性质 |
|---|---|---|
| **误剪** | 人标成 `asmr` 的片段里，被判 `cut` 的秒数 | **硬约束**。丢的是内容，用户拿不回来 |
| **残留** | 人标成 `talk` / `inactive` / `other` 的片段里，被判 `keep` 的秒数 | **优化目标**。切得不干净，片子还能用 |

两者不对称是有意的。十几分钟的废话留在片子里，用户拖一下进度条就过去了；剪掉的
内容则是**永久丢失**，导出之后无从恢复。所以调参的规则是「先划一条误剪预算线，再
在预算内找残留最低的」，而不是把两个数加权成一个总分。

预算线要锚在**基准**上，不能锚在「本轮最低误剪」上。后者看着等价，其实是在给
「少切」发奖金：切得越少，误剪必然越低，那个选项就会把门槛拉到最低，把其余选项
全判成超标——最后选中一个残留更差、只是切得更少的组合。

### 一个容易踩的坑：`cut` 总量不是独立指标

从上面两个定义能直接推出：

```
cut 总量 ≡ 误剪 + （该切片段总时长）- 残留
```

右边那几个一确定，cut 总量就定了。所以它**不提供任何额外信息**，列出来只是方便
看出「这一轮动的是切的总量还是切的位置」。如果残留的每一次下降都被 cut 总量的
等量上升抵消，那这一轮并没有在找准边界，只是在同一根杆子上滑。

### 残留要按标签拆开看

`talk` 的残留该找语音检测，`inactive` 的残留该找静默检测——两套完全独立的检测器。
混成一个数就不知道该动哪个旋钮，甚至可能一直在调一个对当前问题毫无影响的参数。
所以 `_sweep_vad.py` 会把残留按人工标签分开报。

## 为什么片段要分层抽

按时间随机抽的话，绝大多数片段会落在「模型判该留」里（实测一条素材上是 95%），
而模型切掉的那部分本来就少，不单独抽几乎抽不到。于是按模型的三组判断分别配额，
每一组的判对率才能单独算出来。

配额写在登记表的 `plan` 里，按「该组素材总量」和「上一批的短板」定：某一组的素材
总量小到抽不出足够多的独立位置时，配额得压到别处；上一批哪一组的判对率置信区间
宽到没法用，这一批就把配额挪过去。

## 盲标

片段输出时**打乱顺序**，文件名用不透明的编号，分组写到另一个文件（`_answer_key.csv`）
里。标注的人看不到模型的判断，才不会被它带跑。标注期间不打开对照表，是这个流程里
最容易破也最要紧的一条纪律。

## 一个设计上的要点

**标注记的是原片绝对时间上的内容**（`_answer_key.csv` 里的起点秒 + 时长秒），不是
「模型第几段」。所以以后怎么改算法、切点怎么移动，这批标注都还成立，**不用重标**。

代价是对照表里那份「模型判断」是**生成时**的快照，跑完新算法就过期了。要拿新算法
算分得重跑（`_sweep_vad.py` 按当前代码重算每个窗口），别看那份快照。

## 怎么用自己的素材跑

1. 把 `_materials.example.json` 复制成 `_materials.local.json`，按里面的结构填上
   自己的素材。这份文件不进版本管理——它记的是本地媒体库路径。

2. 跑分析、抽片段：

   ```bash
   python _run_analyze.py <素材名>
   python _make_labeling_set.py <素材名>
   ```

3. 人工标注 `<语种>/<素材名>/labels.csv`。

4. 出报告、扫参数：

   ```bash
   python _report.py <素材名>
   python _sweep_vad.py <素材名>
   ```

素材名支持**唯一前缀**，`example` 能指到 `example_20260101`。不给素材名时用登记表
里的 `default`。

## 脚本

| 脚本 | 干什么 |
|---|---|
| `_materials.py` | 登记表的读取器。**本身不含素材数据**，数据在 `_materials.local.json` |
| `_run_analyze.py` | 跑一遍分析，产出 `segments.json` |
| `_make_labeling_set.py` | 分层抽样、切片段、生成 `labels.csv` 和对照表 |
| `_report.py` | 把标注和模型判断对起来，出交付物用的绝对指标 |
| `_sweep_vad.py` | 在已标注片段上扫 VAD 参数，按误剪预算选点 |
| `_inspect.py` | 看某个素材的分段构成，用来定下一套标注的配额 |

同一语种标多份素材时，判定标准要保持一致——中途换标准，两份就不能合并着看了。
**不同语种更要分开统计**：日语准不代表韩语准。目录按 `<语种>/<素材名>/` 分开正是为此。
